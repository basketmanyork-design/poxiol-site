# Inquiry reception and handoff SOP

The source reveals a Formspree endpoint and public contact links, but not a verified lead owner, backup, inbox rule, notification receipt, OKKI connection or SLA. Their actual names and private addresses belong in the team's secure operations configuration, not this public repository. `OWNER=UNVERIFIED`, `BACKUP=UNVERIFIED`, `NOTIFICATION=NOT_TESTED`, `OKKI=NOT_CONNECTED_OR_NOT_VERIFIED`.

At each business-day handoff, the assigned owner should compare Formspree accepted submissions with email notifications and OKKI records for the same window; reconcile by provider receipt ID where available and otherwise by a controlled internal reference. Inspect spam/failed-notification queues. A missing notification must trigger retrieval from saved submissions, not deletion or a buyer request to submit twice. Mark test submissions separately and exclude them from lead metrics. For each real buyer, check product lines/quantities, required in-hand date, country/postal information and one contact method, then follow the team's current inquiry response process. A WhatsApp click is an outbound link event, not a received inquiry.

If the form status is unconfirmed, ask the buyer to check with the team before re-sending. The frontend holds an uncertain draft during the current page session, but the provider's duplicate behavior is not proven. If the receiver, notification or CRM fails, pause ad traffic, keep existing records, inspect provider logs/inbox and restore the chain through the authorized operations owner. Production testing requires its own explicit authorization and a labeled test receiver/notification destination.
